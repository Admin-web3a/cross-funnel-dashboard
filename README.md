# Cross-Funnel Dashboard

Сквозная воронка: трафик → трипвайер → диагностика → отдел продаж → выручка.

**Дашборд:** https://admin-web3a.github.io/cross-funnel-dashboard/

## Чем отличается от md-dashboard и petrock-dashboard

Те дашборды отвечают на вопрос «сколько заявок пришло на лендинг» и считают **лиды**
внутри одной воронки. Этот отвечает на вопрос «сколько людей мы довели до денег»
и считает **контакты**, склеивая четыре воронки amoCRM по `contact_id`:

| | Money-Dick / PetRock | Cross-Funnel |
|---|---|---|
| Единица счёта | лид (сделка) | контакт (человек) |
| Охват | один лендинг | трипвайер + диагностика + ОП |
| Конечная метрика | конверсия в оплату трипвайера | выручка на лид воронки (RPL) |

Расхождение в несколько процентов между дашбордами — норма: один человек может
создать несколько сделок.

## Терминология

Трёхчастная статья с покупкой AFK — это **трипвайер-воронка**, а не «контентная».
Канал трафика (органика YouTube, Telegram, платный Meta) — отдельное измерение,
поэтому «контентный лид» некорректный термин. Вклад контент-завода измеряется
фильтром «Тип трафика → Органика».

## Что внутри

- **Причинно-следственная проверка.** Сделка ОП засчитывается трафику, только если
  создана позже лида трипвайер-воронки. Без этой проверки атрибуция завышалась в 13 раз.
- **Разделение линейной воронки и путей в ОП.** Вход в отдел продаж не является
  следующим шагом воронки: большинство контактов попадают туда параллельным путём.
- **Разложение микса.** Показывает, вызван ли рост конверсии сменой долей источников
  или реальным сдвигом. Защита от ложных выводов при изменении структуры трафика.
- **Разрез по единице контента.** `utm_content` содержит ID видео YouTube для органики
  и ID объявления Meta для платного трафика.

## Устройство

```
generate_report.py   — тянет 4 воронки из amoCRM, склеивает по contact_id
template.html        — шаблон с плейсхолдерами __DATA__, __DIAG__, __UPDATED__ и др.
docs/index.html      — результат, его раздаёт GitHub Pages
```

Зависимостей нет, только стандартная библиотека. Вся фильтрация — на клиенте,
данные вшиты в страницу как JSON.

## Запуск локально

```bash
export AMO_TOKEN=...
python3 generate_report.py
python3 -m http.server 8777 --directory docs
```

## Обновление

GitHub Actions запускает `generate_report.py` каждый час и коммитит `docs/index.html`
в `main`. Секрет `AMO_TOKEN` — на уровне репозитория. Pages раздаёт `main` + `/docs`.

## Известные ограничения

- Тип трафика (органика или платный) определяется по списку источников вручную,
  потому что `utm_medium` занят под идентификатор подрядчика.
- UTM в трипвайер-воронке и в отделе продаж лежат в разных полях amoCRM,
  поэтому склейка идёт по `contact_id`, а не по меткам.
- Часть контактов приезжает с нераскрытыми макросами `{{ad.id}}` — такие лиды
  не атрибутируются. Счётчик выведен в карточке «Качество атрибуции».
